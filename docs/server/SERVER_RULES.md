# Server Rules

마지막 갱신: 2026-06-10

이 문서는 `icecoke-cobblemon` 개인 서버의 플레이 룰과 운영 기준을 정리한다.

## 서버 성격

| 항목 | 기준 |
| --- | --- |
| 용도 | 개인용 Cobblemon 게임 서버 |
| 공개 여부 | 비공개 |
| 접속 범위 | LAN 또는 관리자가 허용한 제한된 환경 |
| 운영 우선순위 | 안정성, 월드 보존, 단순한 운영 |
| 확장 | 외부 연결과 공개 운영은 별도 과제 |

## 플레이 룰

- Cobblemon 중심 플레이를 기본으로 한다.
- 일반 Minecraft 적대 몬스터는 꺼 둔다.
- 죽었을 때 인벤토리, 가방, 경험치는 보존한다.
- RCTMod 기본 15레벨 캡은 사용하지 않는다. 현재 관장 진행은 CobbleBuilds 배지 기준이며, RCTMod 레벨캡은 `initialLevelCap=100`으로 둔다.
- RCTMod 자연 스폰 일반 트레이너는 배지 수와 자동 연동되지 않는다. 현재는 파티 최고 레벨 기준 허용 차이를 `maxLevelDiff=5`로 낮춰 과한 고레벨 스폰을 완화한다.
- 월드 파괴나 대규모 구조물 붙여넣기는 백업 이후에만 진행한다.
- 관장, 보상, NPC 변경은 백업, 콘솔 검증, 문서 기록을 남긴다.

## 현재 게임 설정

| 설정 | 값 | 의미 |
| --- | --- | --- |
| `spawn-monsters` | `false` | 일반 적대 몬스터 비활성화 |
| `spawn-animals` | `true` | 일반 동물 활성화 |
| `spawn-npcs` | `true` | NPC 활성화 |
| `difficulty` | `easy` | 기본 난이도 쉬움 |
| `keepInventory` | `true` | 사망 시 아이템/가방/경험치 보호 |
| `max-players` | `2` | 개인 서버 기준 소수 접속 |

## 모드 운영 룰

- 새 모드를 추가하기 전에 기존 설정, gamerule, 데이터팩, 현재 모드 기능으로 해결할 수 있는지 먼저 본다.
- 클라이언트도 필요한 모드인지 서버 전용 모드인지 구분한다.
- 방송, 녹화, 보이스챗, 쉐이더, 선택 그래픽/사운드 연출 모드는 현재 개인 서버 기준에서 제외한다.
- 서버 모드가 바뀌면 `MODS_AND_CLIENT.md`를 갱신한다.

## 관장 운영 룰

- 관장 콘텐츠는 탐험 목표로 사용한다.
- 타입/바이옴 컨셉은 `GYM_CONCEPT.md`를 따른다.
- 포켓몬 팀은 `GYM_TEAMS.md`를 따른다.
- 현재 월드에는 8개 gym marker와 8개 gym leader spawner marker가 있다.
- 기본 건물이 있는 6개 gym은 배치와 하단 보정을 완료했다.
- 실제 관장 NPC 생성, 전투, 배지/보상 흐름은 플레이어 근접 인게임 확인을 남긴다.
- 동적 난이도는 배지 수 기반 단계식으로 검토한다.

## 금지/보류

- 공개 서버처럼 경제, 상점, 랭킹을 먼저 붙이지 않는다.
- 월드 파일을 직접 덮어쓰는 작업은 백업과 복구 검증 전까지 하지 않는다.
- 클라이언트 접속 조건이 바뀌는 모드 변경을 문서 없이 진행하지 않는다.
